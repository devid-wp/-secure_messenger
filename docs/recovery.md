# Потеря пароля, устройства и восстановление

## Разделение понятий

- **Восстановление аккаунта** возвращает право войти и управлять user record.
- **Восстановление E2EE-истории** требует ключей устройства или отдельного
  encrypted backup.

Пароль не является E2EE master key. Сервер не может восстановить историю после
обычного password reset.

## Потерян пароль, есть доверенное устройство

1. Пользователь инициирует reset на доверенном устройстве.
2. Устройство подтверждает запрос своим device signature key.
3. Сервер заменяет password verifier и отзывает остальные login sessions.
4. MLS identity, локальная история и safety codes не меняются.
5. Security event синхронизируется между собственными устройствами.

## Потерян пароль, устройств нет

В v1.0 используются одноразовые recovery codes, выданные при регистрации и
хранимые сервером только как hash.

1. Recovery code возвращает доступ к аккаунту, но не к старым E2EE keys.
2. Создаётся новая device identity.
3. Аккаунт получает состояние `identity_reset`.
4. Старые устройства отзываются.
5. Контакты видят обязательное предупреждение об изменении safety code.
6. Для групп новый device добавляется новым MLS Commit.
7. Старая локальная история недоступна.

Если нет ни устройства, ни recovery code, автоматического восстановления нет.
Ручная поддержка не должна обходить криптографическую идентичность.

## Потеря одного устройства

1. Пользователь отзывает device с другого доверенного устройства.
2. Сервер немедленно блокирует session и отправку от device.
3. В каждом чате создаётся MLS Remove/Commit.
4. Только после Commit остальные устройства отправляют новые application
   messages.
5. Устройство не получает новые ciphertext.

Отзыв не стирает уже сохранённый plaintext и не отменяет компрометацию прошлых
epoch secrets. Пользователь должен считать прочитанную историю раскрытой.

## Добавление нового устройства

- Password login создаёт только `pending` device.
- Активация требует QR/short-authenticated-string подтверждения существующим
  активным устройством.
- Подтверждающее устройство подписывает привязку нового credential.
- Новый device добавляется отдельным MLS Commit в каждый чат.
- По умолчанию новый device получает только новые сообщения.
- Передача старой истории — отдельный direct device-transfer, инициированный
  пользователем; сервер передаёт только E2EE stream.

## Потеря всех устройств

В v1.0 старые сообщения необратимо недоступны. Это осознанная гарантия: у
сервера нет escrow key. Пользователь может восстановить аккаунт и начать новые
криптографические сессии, но не старую историю.

## Удаление аккаунта

1. Все devices переводятся в `revoked`.
2. В чатах создаются Remove proposals/commits другими авторизованными
   участниками либо чат блокируется до commit.
3. Сервер удаляет queued ciphertext и KeyPackages пользователя.
4. Локальные клиенты удаляют local store key.
5. Минимальный tombstone сохраняется только для предотвращения replay и
   выполнения retention policy.

## Будущий encrypted backup

Cloud backup не входит в v1.0. Его добавление потребует:

- отдельного случайного recovery secret, не производного только от пароля;
- client-side AEAD и versioned manifest;
- явного opt-in;
- проверки целостности и rollback protection;
- rate limiting для попыток восстановления;
- security review формата и жизненного цикла recovery secret.

До выполнения этих условий сервер MUST NOT загружать экспорт локальных ключей.
