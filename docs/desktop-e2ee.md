# Desktop E2EE implementation

Secure Messenger is introducing a Tauri 2 desktop client around the existing
React interface. The native Rust boundary lives in `frontend/src-tauri`; the web
client remains available for UI development but must not claim E2EE.

## OpenMLS device bootstrap

- Tauri desktop shell and a minimal capability policy.
- A lazy JavaScript bridge that does not load Tauri APIs in a browser.
- A Rust `crypto_status` command that becomes available only after native MLS
  identity and provider state exist.
- No fallback encryption. Sending must be gated when the MLS service is added.
- A 256-bit device master key generated by the operating-system RNG.
- The master key is persisted only as a versioned Windows DPAPI envelope bound
  to the current Windows user.
- The desktop refresh session is held by Rust instead of browser
  `localStorage` and persisted in a Windows DPAPI-protected envelope. On
  restart, the client restores it and rotates it through the refresh endpoint;
  an explicit logout clears the persisted session and locks the vault.
- Private key bytes are not exposed by any Tauri command.
- Serialized OpenMLS provider state is loaded from and atomically persisted to
  the native-only, versioned DPAPI boundary at
  `secure-vault/openmls-state.dpapi`.

The client pins OpenMLS `0.8.1` and
`MLS_128_DHKEMX25519_AES128GCM_SHA256_Ed25519` (IANA `0x0001`). It does not
negotiate another suite or provide a JavaScript cryptographic fallback.

After desktop authentication, `mls_initialize` loads or creates one Ed25519
signature identity for the server-issued device ID, loads the OpenMLS provider,
generates TLS-serialized KeyPackages, and persists their private HPKE material.
Only the public identity key, fingerprint, suite ID, and public KeyPackages
cross Tauri IPC. The signature key and OpenMLS provider map remain in Rust and
the DPAPI-backed vault.

FastAPI exposes the public identity directory, one-time KeyPackage claiming,
and an authenticated inventory endpoint. The client targets 20 available
packages and publishes only the deficit after login and token refresh. New
packages expire after seven days.

The current milestone does **not** encrypt messages and is not an E2EE release.

The active React application still receives its bearer token in memory because
the current HTTP and WebSocket clients run in the WebView. The improvement in
this milestone is removal of persistent browser storage, not removal of the
token from the renderer process. The rotating refresh session is persisted
through the native DPAPI boundary; the access token remains memory-only.

The DPAPI envelope is stored below the Tauri application-data directory in
`secure-vault/master-key.dpapi`. Corrupt or unsupported envelope versions fail
closed; they are not silently replaced.

## Windows prerequisites

1. Rust stable through rustup.
2. Microsoft C++ Build Tools with **Desktop development with C++** and a Windows
   SDK. This supplies the MSVC `link.exe` required by Tauri.
3. Microsoft Edge WebView2 (normally already present on supported Windows).

Run the desktop development shell from `frontend`:

```powershell
npm run desktop:dev
```
